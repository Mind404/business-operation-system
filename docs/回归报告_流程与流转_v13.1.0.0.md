## 二、本轮修复的问题

1. SpiffWorkflow 导入名大小写：包名是 `SpiffWorkflow`，不是 `spiffworkflow`。
2. 网关条件读取 `task.data` 而非 `workflow.data`：审批时把 `decision` 同时写入当前 `spiff_task.data`。
3. WBS `collect_my_todos` 兼容：平台待办补齐 `wbs_code / project / days_left`，避免工作台模板取值报错。
4. 平台管理员兜底：不仅按 `assignee` 匹配，`admin` 角色同时命中 `admin` 与 `platform_admin`。
5. 动作失败重试：失败前先保存 SpiffWorkflow 序列化状态，重试才能从失败任务继续。
6. WBS 发起失败回滚：流程引擎启动失败时，把项目和任务审批状态恢复为原值，避免卡在「待审批」。
7. 审批分支校验：审批节点必须配置 `approve` 与 `reject` 分支，保存模板时提前报错。

## 四、当前边界与下一阶段建议

### 已可用

- 通用审批、WBS 项目审批、WBS 任务审批、会签演示
- 审批同意/驳回/退回
- 统一待办、流程中心、管理端模板/版本/实例/订阅/发件箱/审计导出
- 插件动作回调、失败重试、事件投递

### 暂未做

- 可视化 BPMN 画布：当前是 JSON 编辑器
- 并行网关：生成器支持 `parallel` 节点类型，但没有内置模板和真实并行分支验证
- WBS 任务页内联发起按钮：任务审批 API 和动作已具备，页面入口还没加
- 旧 `approval_requests` 数据迁移：新流程使用新表，旧审批保留
- Windows 真机启动验证：依赖已装入包，需在目标 Windows 机器上实际启动一次

### 建议顺序

1. 先在 Windows 真机启动 v13.1.0.0，确认流程中心、发起、审批、WBS 试点四项可用；
2. 再决定是否把 WBS 任务页也接进来；
3. 若确认流程配置要交给非技术人员，再做节点式表单或 BPMN 画布；
4. 并行网关等真实业务出现“多部门同时审批”时再补，不提前堆功能。
