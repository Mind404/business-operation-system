# v13.6.2.0 统一审批出口与遗留清理

日期：2026-11-20

## 一、已执行

1. WBS 项目审批
   - 删除业务页 `/wbs/<pid>/approve` 的本地通过/驳回。
   - 删除新建项目表单里的“指定审批人”；普通用户提交前校验流程是否已配置，未配置直接拦截。
   - 删除详情页“平台审批流”手动发起按钮及 `/workflow/start/wbs/project/<pid>` 路由。
2. WBS 任务审批
   - 删除 `/wbs/project/<pid>/tasks/approve` 批量通过/驳回及页面按钮、`batchApprove` 脚本。
   - 保留“重新提交”动作，但必须先有流程托管，否则返回 409，不再落回本地审批。
3. 版本发布
   - 删除 `/version_plan/versions/<no>/sign` 发布签核接口与页面签核表单。
   - 删除 `version_plan_signoffs` 建表与常量；发布门禁只保留 7 项业务确认清单。
   - 发布审批统一在流程中心完成，通过后自动发布并生成 Release Note。
4. 遗留表和 helper
   - 删除 `tasks`、`approval_requests` 表及 `plugin_system.submit_approval/review_approval`。
   - `schema.sql` 不再创建这两张表；新增迁移 v10 对老库自动 `DROP`。
   - 工作台插件登记不再声明 `tasks`；AI 上下文排除列表同步清理。

## 二、影响与边界

- 管理员/平台管理员仍按既有规则免审批直接操作，但会写操作流水；这是“免审批”，不是第二个审批出口。
- 普通用户提交 WBS 项目/任务、版本冻结/解冻/发布，必须已有可用流程；流程未配置时业务页直接拦截，不会生成“待审批但无人可批”的记录。
- 历史 `approval_status` 字段保留，用于状态展示与流程写回；删除的是本地审批动作，不是状态字段。
- 旧库升级到 v13.6.2 时，迁移 v10 会自动删除 `tasks`、`approval_requests`；如旧库还有业务数据，会一并删除，升级前需备份。

## 三、第 3 项分析：是否把“流程与审批”并入工作台首屏

### 保留独立页的优势

- 职责分层：工作台是“我的待办/通知”消费面，流程页是“定义、绑定、触发、实例、日志”管理面，混在一起会让普通用户看到大量与自己无关的配置。
- 权限隔离更简单：流程配置主要面向平台管理员，审批面向所有人；独立页可以按角色分别控制导航和入口。
- 深度操作有空间：实例详情、审批历史、节点日志、失败重试、流程定义编辑，首屏卡片放不下。
- 稳定性更好：工作台异常时，审批中心仍可作为独立兜底入口。
- 性能更好：首屏只聚合当前用户待办，不用加载全量流程配置。

### 并入工作台首屏的优势

- 用户只记一个入口，减少“待办在这里、审批在那里”的认知负担。
- 少一套导航和页面壳，重复的统计、空状态、通知样式可以合并。
- 对 60 人团队、以审批为主的使用场景，打开首页即可处理，路径更短。

### 并入的代价

- 首屏变重：流程配置、实例列表、审批历史会把个人工作台变成“管理后台”。
- 权限混杂：普通用户会看到流程定义/绑定等管理内容，需要额外隐藏逻辑。
- 深度功能仍要独立页：最终很可能变成“工作台里再嵌一个完整流程页”，代码和交互更复杂。
- 维护成本：两套入口合并后，模板条件、路由守卫、移动端布局都要重做，回归面较大。

### 建议

不建议把完整流程页塞进工作台首屏。建议保留独立页，做“摘要 + 深链”：
- 工作台保留“流程与审批”摘要卡，展示待我审批的前 3–5 条；
- 卡片底部固定“查看全部审批”跳到独立页，并带上当前用户过滤；
- 独立页只承载配置、实例详情和历史，不重复工作台的通知流；
- 导航上把独立页命名为“审批中心”，工作台卡片叫“待我审批”，语义直接对应。

这样既只有一个“审批动作出口”，又不会把管理配置压到每个人首页。是否采用这个折中方案，等你确认。
