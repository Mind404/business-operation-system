## 一、这版解决的问题

v13.3 把「插件状态变更节点 → 绑定流程 → 工作台发起」的链路打通了，但真正上手时还有三个卡点：

1. **流程 Key 不知道填什么**：业务人员不理解「Key」是什么，填错还会报格式错误。
2. **审批人值只能手打账号**：人一多就记不住，也没有搜索，容易填错人。
3. **不知道每个插件有哪些状态变更点**：节点目录页只列了名字和一行说明，搭建流程的人不知道「这个节点什么时候发生、会带什么数据、默认怎么审」。

## 二、功能改动

### 2.1 流程 Key 自动生成（`workflow_engine.generate_def_key`）

- 新建流程默认**不显示 Key 输入框**，只显示「保存时自动生成：xxx」；勾选「我要自定义」才出现输入框。
- 生成规则：绑定了状态变更节点 → 直接用节点键（`wbs.task.completed` → `wbs_task_completed`）；未绑定 → `flow_日期`；重名自动追加 `_2`、`_3`。
- 已有流程的 Key 仍只读，避免历史实例与新版本脱节。
- 自定义 Key 做了合法性校验，中文/非法字符会明确提示，而不是静默忽略。
- 修复 v13.3 遗留：设计器里的「触发这个流程」区块原来在 `<form>` 外面，选了节点点保存**根本提交不上去**；现已移入表单并随保存一起提交。

### 2.2 审批人接入用户管理（`actor_options` + `/workflow/admin/api/actors`）

- 「审批人值」从纯文本框改为**可搜索下拉**：输入姓名、账号或部门，实时筛选后点选，选中后显示「已选：产品经理（product）」。
- 数据直接来自平台「用户管理」的 `users` 表，只取启用且未删除的用户；角色下拉列出平台角色及人数，管理员角色人数已合并 `admin + platform_admin`。
- 切换审批人类型时清空旧值并给出新提示，避免角色值残留在用户类型里。
- 保留手填能力：接口不可用时仍可直接输入账号，不阻断建流程。
- 新增只读接口 `GET /workflow/admin/api/actors?type=user|role&q=`，仅平台管理员可访问，普通用户返回 403。
- **修复 v13.3 遗留缺陷**：`record_field`（业务字段）审批人写进定义时只写了 `value`，而运行期解析读的是 `field`，导致无论填什么字段都回落到 `owner`。现在两者同时写入，并补了解析回归。

### 2.3 状态变更节点说明子页（`/workflow/admin/events/guide`）

- 新增「📖 节点说明」页，按插件分组用表格列出每个节点：
  - 什么时候会发生（业务动作描述）
  - 会带进流程的业务数据（字段中文名 + 字段键，方便配置「业务字段」审批人）
  - 推荐审批链（节点顺序）
  - 当前是否已接入、触发的流程名与触发方式
- 页面底部附「三步上手」和常见问题（Key 要不要填、审批人怎么选、一个节点能绑几条流程、绑错怎么办）。
- 入口：流程管理页头、状态变更节点页顶部。
- 节点目录页每行也补上了「携带数据」「推荐审批链」，不用来回跳页。
- 节点顺序改为按插件注册顺序展示（项目创建 → 项目审批结果 → 任务创建 → 任务进度 → 任务完成），不再按字母排序打乱业务先后。
