# v13.6.0.0 回归与冷审查报告

日期：2026-11-20
版本：`13.6.0.0`
范围：工作台插件化、插件通知、人员关联、事件流水保留期；承接 v13.5 审批统一基线。

| 用户要求 | 落地方式 | 状态 |
|---|---|---|

| 同意事件流水保留期 | `wf_event_log` 保留 180 天，且最多 50 万条；启动时按自然日节流清理 | 已落地 |
| 审批统一入口 | 工作台只保留「流程与审批」统一入口，不恢复 WBS 本地审批；流程待办作为 `workflow` 插件模块置顶 | 保持 |
| 解冻只给管理员 | 沿用 v13.5 门禁与权限：普通用户、产品负责人、版本负责人均不能直接解冻 | 保持 |
| 驳回通知进入「我的工作台」 | 新增 `wf_notifications`；流程最终驳回后通知发起人，工作台按插件分组展示、可标已读、可跳转业务页 | 已落地 |
| 工作台废弃计数板块、按插件分化、关联真实人员 | 删除 WBS Hero 逾期卡、4 个 KPI、旧 `tasks` 待办、跨插件总计数与 `wf_stats`；改为插件模块聚合；会话身份归一为用户管理中的真实用户；WBS/版本待办带 `owner_user_id/username/display_name` | 已落地 |

## 二、工作台新结构

1. 顶部欢迎条：显示用户管理中的显示名、账号，不再放任何全局计数。
2. 插件通知：按来源插件分组，展示标题、正文、时间、未读状态；支持全部标为已读。
3. 流程与审批：统一审批入口；待我发起、待我审批、我发起的、运行中/异常放在同一面板。
4. 插件待办：由已启用插件各自提供 `workbench_modules(db, user_ctx)`；流程模块置顶，WBS、版本规划依次排列。
5. 插件内部保留自己的筛选数字（如 WBS 的待办总数/逾期/3 天/7 天），用于本插件导航；不再有跨插件汇总总数。

## 三、契约与数据

- 新插件契约：`workbench_modules(db, user_ctx) -> list[{plugin_id, plugin_name, icon, kind, title, items}]`。
- 兼容旧契约：`my_todos(db, username)`；未提供新契约的插件仍可接入。
- 待办 item 统一字段：`title/url/status/due/days_left/level`，可附 `owner_user_id/owner_username/owner_display_name`。
- 通知表 `wf_notifications`：按「实例 + 用户 + 事件」幂等，唯一索引兜住并发 check-then-insert。
- 通知跳转只允许站内单斜杠路径；写入时归一化，打开时二次校验，拒绝 `//evil.example.com`、反斜杠、换行等写法。
- 事件流水清理：`prune_event_log(db, keep_days=180, max_rows=500000, force=False)`；先删超期，再按 id 从旧到新删超量。
- 版本产品负责人保存为账号；显示为「姓名（账号）」；历史未匹配显示「未关联账号」；同名显示名不猜测归属。

## 四、冷审查发现并修复的问题

| # | 问题 | 影响 | 修复 |
|---|---|---|---|
| 1 | 模板引用不存在的 `workflow.index` | 工作台渲染 500 | 改为 `workflow.my_tasks` |
| 2 | 版本待办 SQL 少写 `% _workbench_table(...)` | SQL 语法错误、模块被吞 | 补齐表名绑定 |
| 3 | 通知查询 `read_at=''` 单引号写法 | SQL 语法错误 | 改为双引号 Python 字符串 |
| 4 | 版本 helper 关闭请求级 `g.db` | 后续 WBS 模块与通知路由 500 | 移除错误的 `close()`；独立插件连接才关闭 |
| 5 | 通知 check-then-insert 并发重复 | 同一事件多条通知 | 唯一索引 + `IntegrityError` 回查 |
| 6 | `notify_user` 用 `ORDER BY id DESC` 取最新行 | 并发下可能返回别人的通知 | 插入后保存 `lastrowid` 精确回查 |
| 7 | 工作台只遍历静态 `PLUGINS` | 漏掉动态注册的 `version_plan` | 改为注册表/manifest 遍历 |
| 8 | 驳回通知在写回前发出 | 写回失败时误报“已驳回” | 移到写回成功后；失败转 error 不发 |
| 9 | 工作台 Hero 多出“流程中心”按钮 | 与统一入口重复，触发 v13.2 旧断言失败 | 删除冗余按钮 |
| 10 | 通知链接允许 `//evil.com`、反斜杠 | 可被用作站外跳转 | 写入/打开双重校验，并补回归断言 |
| 11 | WBS 按显示名匹配，同名时会串号 | 两人同名时互相看到对方任务 | 显示名仅在用户管理唯一时参与匹配；重名时只按账号，宁可不出待办 |
| 12 | 重名时别名列表为空仍拼 SQL | `WHERE ()` 语法错误 | 空别名直接返回空列表 |
| 13 | 工作台按显示名解析身份取第一条 | 同名时可能登录成别人的工作台 | 重名时返回未锚定身份，不展示个人待办/通知 |

## 六、仍然存在的边界

1. CSRF 防护按用户决定暂不实现。
2. `wf_notifications` 本身未设置独立保留期；本版只对 `wf_event_log` 执行 180 天/50 万条策略。
3. 存量版本产品负责人 `张工/李工/王工` 未自动映射到用户管理账号，界面显示「未关联账号」，不会产生版本个人待办；需要业务侧补录或一次性映射。
4. 插件内部的筛选数字（WBS 四格、流程 Tab 数量）保留，属于插件局部导航；顶层跨插件计数已删除。
5. 工作台通知默认最多展示最近 50 条；未读数按全量统计。
6. 未做基于像素比对的自动化 UI 回归；本版用 Flask 页面断言 + 真实浏览器截图验收覆盖主要布局。

## 七、结论

六项要求均已按用户口径落地；审批仍为单一入口，解冻仍只给管理员；工作台已从“平台计数看板”转为“按插件分化的个人工作台”，人员统一关联用户管理。冷审查发现的 13 个问题全部修复并加入回归断言，v13.2-v13.6 全部基线 0 失败，可以进入打包与交付。
