# 审批中心 v13.8.0.0

## 为什么合并
v13.7 有两个管理员入口：「审批规则中心」负责配置，「流程运行记录」负责看运行，数据和职责不重复，但概念重复、入口分散。v13.8 合并为一个「审批中心」，平台管理员只记一个地方。

## 一个入口，三个页签

| 页签 | 解决什么问题 | 主要内容 |
|---|---|---|
| 规则配置 | 哪些业务要审批、按什么范围、送给谁 | 业务节点卡片、审批链、未配置直通记录 |
| 运行记录 | 审批走到哪、卡在谁、有没有异常 | 模板/实例/待审批/异常/死信统计、最近实例、发件箱 |
| 高级设置 | 外来插件怎么接、流程模板怎么管 | 外部插件令牌、流程模板、事件订阅 |

侧栏只保留「审批中心」。旧地址仍然可用：
- `/workflow/admin` → 打开「运行记录」页签
- `/workflow/admin/rules` → 打开「规则配置」页签
- `/workflow/admin/events` → 旧「状态变更节点」高级页，保留给排障

## 规则配置怎么改得更傻瓜
- 不再让人填 Key、选状态点编码。页面直接说「哪个业务要审批」「哪些业务需要审批」「排审批人」。
- 业务节点按插件分组，每条规则直接显示：适用范围、流程名、启停、审批链。
- 审批链用「发起 → 审批人（步骤名/备份人）→ 审批完成」的胶囊节点展示，不再只显示一串账号。
- 未配置节点明确写「发起 → 直接放行（不审批，留记录）」，不会让人误以为系统坏了。
- 编辑规则改成三步向导，右侧固定「审批链预览」，改一步看一步：
  1. 哪个业务要审批
  2. 哪些业务需要审批（全部 / 指定产品 / 指定项目类型）
  3. 排审批人（每步主审批人 + 可选备份人，可增删步骤）

## 规则口径（不变）
- 只有平台管理员能配置，普通用户只执行。
- 配置对象是「业务状态变更点」，不是流程模板。
- 一条生效规则 = 一个状态变更点 + 一个适用范围；同一范围不能有两套生效逻辑。
- 指定产品/指定项目类型优先于「全部」。
- 没配规则时普通用户直接执行业务，不阻塞；系统写「未配置审批规则，本次直通」流水。
- 每步一个主审批人 + 一个备份人；主审批人失效先转备份，再转平台管理员。
- 不做审批时限；只记录时间、操作人、意见。
- 规则只对新提交业务生效，不追溯历史。
- 业务状态与审批状态分开显示；驳回必须写原因并指定退回对象。

## 运行记录怎么看
- 五个数字：流程模板、运行中实例、待审批任务、异常实例、死信事件。
- 最近实例表把「审批状态」单独一列，业务状态由插件自己展示，避免把「审批通过」误当成「业务完成」。
- 发件箱失败重试 5 次后进入死信，异常和死信都在这里暴露。

## 升级注意
- 老库启动自动迁移到 schema_version=11：WBS 增加 `project_type`，审批规则增加适用范围。
- 旧规则默认归入「全部」。如果旧规则是「全部 + 确认」，普通用户提交任意项目类型都会命中；要按项目类型直通，需要编辑旧规则或删除后重配。
- 旧流程模板设计器仍保留在高级设置，日常配置不需要进入。
