# 流程与流转引擎 · 实践说明 v1

> 版本：13.1.0.0　分支：`feature/workflow-engine-v1`　日期：2026-11-20

## 一、这次做了什么

在现有 Flask 业务系统上，新增一套**平台级流程与流转能力**。执行层复用开源 BPMN 引擎 **SpiffWorkflow 3.2.0**，平台只做自己必须做的事：流程定义版本管理、审批任务、统一待办、插件动作回调、审计与失败重试。

不是替换现有 WBS 审批，而是先做一条可运行、可验证的“平台流程”通道，WBS 作为第一个试点接入。

## 二、为什么用 SpiffWorkflow

- 纯 Python，能直接放进现有 Windows 便携包，不需要 Java、Node、Docker 或额外常驻服务。
- 支持 BPMN 2.0 的 `userTask`、`manualTask`、排他网关，正好对应“审批节点”和“插件动作节点”。
- 工作流可序列化为 JSON 存进 SQLite，实例状态可恢复、可重试。
- LGPL-3.0，内部系统使用没有额外合规负担。

平台没有重复造执行引擎，只补了 SpiffWorkflow 不自带的部分：审批人规则、任务列表、会签/或签、业务动作、事件链和发件箱。

## 三、数据模型

所有流程表都在**平台主库** `business.db`，不侵入插件业务库：

| 表 | 作用 |
|---|---|
| `wf_definitions` | 流程模板目录，记录当前版本 |
| `wf_definition_versions` | 每个版本的 JSON 定义 + 自动生成的 BPMN XML + 校验和 |
| `wf_instances` | 流程实例，钉住 `def_key + def_version`，保存 SpiffWorkflow 序列化 JSON |
| `wf_tasks` | 平台审批任务，关联 SpiffWorkflow 的 `spiff_task_id` |
| `wf_events` | 实例事件哈希链，用于审计 |
| `wf_subscriptions` | 插件对流程事件的订阅 |
| `wf_outbox` | 跨插件动作投递箱，失败重试、5 次后死信 |

插件业务数据仍留在自己的库；流程实例只保存 `plugin_id / record_type / record_id` 和上下文快照。

## 四、流程定义格式

管理员在“流程管理 → 新建/编辑模板”里写 JSON，平台自动生成 BPMN。示例：

```json
{
  "key": "wbs_project_approval",
  "name": "WBS 项目立项审批",
  "nodes": [
    {"id": "start", "type": "start", "name": "开始", "next": "approve"},
    {
      "id": "approve",
      "type": "approval",
      "name": "项目审批",
      "assignee": {"type": "role", "value": "admin"},
      "mode": "any",
      "next": {"approve": "apply", "reject": "end_reject", "return": "end_return"}
    },
    {
      "id": "apply",
      "type": "action",
      "name": "写回项目审批状态",
      "plugin": "wbs",
      "action": "wbs.project.set_approval",
      "next": "end_approve"
    },
    {"id": "end_approve", "type": "end", "name": "已通过"},
    {"id": "end_reject", "type": "end", "name": "已驳回"},
    {"id": "end_return", "type": "end", "name": "已退回"}
  ]
}
```

审批人规则：

- `initiator`：发起人
- `user`：指定用户名/姓名，可数组
- `role`：按角色；`admin` 会同时命中 `admin` 和 `platform_admin`
- `record_field`：从业务上下文取字段，如 `owner`
- `project_participants`：从上下文取 `participants`

审批模式：

- `single`：单人
- `any`：或签，一人处理即推进
- `countersign`：会签，全部同意才推进；任一人驳回则取消同节点其余任务

## 五、内置模板

| Key | 用途 |
|---|---|
| `generic_approval` | 通用单节点审批，适合先点一遍看效果 |
| `wbs_project_approval` | WBS 项目立项，审批通过写回项目 `approval_status` 和 `approver` |
| `wbs_task_approval` | WBS 任务审批，审批通过写回任务 `approval_status` |
| `demo_countersign` | 管理员会签演示 |

## 六、页面入口

- **流程中心** `/workflow/`：我的待审批、到期时间、去处理
- **发起流程** `/workflow/start`：选择模板、填标题/业务单号/上下文 JSON
- **实例详情** `/workflow/instance/<id>`：审批任务、流程轨迹、上下文、审批操作
- **流程管理** `/workflow/admin`（仅平台管理员）：模板、版本、实例、事件订阅、发件箱、审计 CSV
- **工作台**：流程待办并入现有“我的待办”分组，显示为“🔄 流程与审批”
- **WBS 项目详情**：平台管理员可点“平台审批流”，走 `wbs_project_approval`

## 七、插件动作回调

内置动作：

- `demo.record_decision`：只记录
- `wbs.project.set_approval`：写回 WBS 项目审批状态/审批人
- `wbs.task.set_approval`：写回 WBS 任务审批状态

外部插件两种接入方式：

1. 启动时调用 `workflow_engine.register_action('plugin.action', handler)`；
2. 在 `plugins/<id>/routes.py` 里实现 `workflow_action(ctx)`，平台会自动发现并调用。

动作失败不会把流程标成“已完成”，而是实例进入 `error`，管理员在实例详情点“重试失败动作”。

流程完成时可发 `workflow.completed` 事件，管理员在“事件订阅”里配置 `plugin_id + event_type + action`，平台写入 `wf_outbox` 异步投递。

## 八、API

```http
POST /workflow/api/instances
Content-Type: application/json

{
  "def_key": "generic_approval",
  "plugin_id": "platform",
  "record_type": "",
  "record_id": "",
  "business_key": "TEST-001",
  "title": "测试审批",
  "context": {"owner": "zhangsan"}
}
```

返回 `instance_id`。另有：

- `GET /workflow/api/instances/<id>`：实例、任务、事件
- `GET /workflow/api/tasks/mine`：我的待审批

## 九、验证结果

在独立 SQLite 测试库上执行流程内核回归，26 项全部通过：

- 4 个默认模板均可启动、生成 BPMN、创建审批任务
- 同意 / 驳回 / 退回
- 或签：一人处理取消同节点其余任务
- 会签：一人同意不推进，两人同意推进；中途驳回取消其余任务
- WBS 项目/任务动作写回
- 越权用户不能审批
- 插件动作失败 → 实例 error → 修复后重试 → completed
- 事件订阅 → 发件箱 → 投递成功
- 定义版本隔离：旧实例钉住 v1，新实例用 v2

Flask 页面回归：

- 平台管理员：流程中心、发起页、管理页、模板编辑、实例详情均 200
- 普通用户：流程中心、发起页、工作台 200；访问管理页被重定向
- 工作台出现“流程与审批”待办分组
- WBS 项目页出现“平台审批流”按钮，点击后项目变“待审批”，审批通过后回写“已通过”

## 十、当前边界

- 管理端是 JSON 编辑器，不是可视化 BPMN 画布；先保证引擎和闭环可运行。
- 内置模板只用了审批、动作、排他网关；`parallel` 节点类型已预留，但尚无内置并行模板。
- WBS 试点只做了项目入口；任务审批已具备路由和动作，页面入口后续再加。
- 没有做旧 `approval_requests` 表的数据迁移；新流程用新表，旧审批代码保持不动。
- 便携包已带入 Windows 版 `SpiffWorkflow` 与 `lxml`，但需在 Windows 上再做一次真实启动验证。
