## 压力测试关键项

- 1200 需求 / 120 版本：列表、详情、需求台账 P95 < 2s。
- 40 个不同账号并发发布同一版本：只生成 1 个流程实例、0 个 5xx、40 条事件全留痕、总耗时 < 10s。
- 8 人并发审批同一任务：仅 1 人成功，任务只记录 1 次通过。
- 200 次 10 线程并发上报：全部成功、全部留痕。
- 30 个 WBS 项目批量立项 → 逐级审批 → 全部写回通过，< 30s。
- 40+ 流程定义下节点目录页 P95 < 3s。
- 主库/插件库 `PRAGMA integrity_check` 均通过；备份包含 120+ 版本。

## 冷审查发现并修复

1. 审批任务并发抢占：原“先查后改”导致两人可同时审批同一节点；改为 `UPDATE ... WHERE status='pending'` 条件更新。
2. 同一业务单号并发上报可能生成多个实例：新增部分唯一索引 + 冲突回查，冲突时返回 duplicate。
3. 普通用户可用别的版本号把其他版本需求退回规划池：移出前校验需求归属产品与版本。
4. 门禁流程被停用/未绑定时，普通用户会回退成直接冻结或发布：改为 fail-closed，拒绝并提示管理员启用。
5. WBS 任务默认审批只有任务负责人自批，没有管理员关口：默认流程增加管理员审批节点。
6. 管理员发布在流程停用时仍被旧签核挡住：管理员口径统一为只校验 7 项确认清单。
7. 压测脚本用 `shutil.copy2` 模拟备份，WAL 数据丢失误报：改用 SQLite backup API，与平台备份一致。
