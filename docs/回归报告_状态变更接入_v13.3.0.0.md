# 回归报告 · 业务状态变更节点接入流程引擎 v13.3.0.0

- 版本：13.3.0.0
- 日期：2026-11-20
- 分支：`feature/workflow-engine-v1`
- 验证环境：Linux 云主机（Python 3.12 + Flask + SpiffWorkflow 3.2.0），临时库副本，不写生产库
- 结论：**v13.3 新增回归 45 项全部通过；v13.2 原有 34 项回归全部通过，无回退**

## 一、这版解决的问题

v13.2 的流程引擎只能由管理员手动创建通用模板、业务人员再到发起页选流程名字。实际使用中「谁该发起、什么时候发起」说不清。v13.3 把主动权交回业务现场：

1. 插件把业务里值得审批的**状态变更**登记成节点；
2. 管理员在流程管理里**看见节点、绑定流程、选择触发方式**；
3. 业务人员在工作台**一键发起**，或让系统自动发起。

## 二、功能改动

### 2.1 流程引擎（`workflow_engine.py`）

- 新增 `wf_triggers`：节点 ↔ 流程绑定，`UNIQUE(def_key)` + `UNIQUE(plugin_id, event_key)`，一个节点只绑一条流程。
- 新增 `wf_trigger_queue`：人工确认模式下的待发起记录，含业务单号、上下文、发起人、处理状态。
- 新增节点注册表：`register_event / event_options / event_catalog / get_event`。
- 新增绑定管理：`bind_trigger / get_trigger_for_def / list_triggers / unbind_trigger / unbind_by_def / set_trigger_mode / set_trigger_enabled`。
- 新增上报入口：`emit_state_change()`，支持 confirm / auto 两种模式、按 `business_key + def_key` 幂等跳过、流程停用时跳过。
- 新增队列操作：`pending_starts / count_pending_starts / start_from_queue / ignore_queue / queue_rows`。
- 新增 `build_default_definition_for_event()`：按节点默认审批链生成可发布流程。
- `stats()` 增加 `pending_starts`、`events` 两个指标。
- 建表全部 `CREATE TABLE IF NOT EXISTS`，老库升级不需要数据迁移。

### 2.2 流程管理端（`workflow_routes.py` + `workflow_events.html`）

- 新增「⚡ 业务状态变更节点」页：按插件分组，逐节点展示触发时机、绑定状态、流程 Key。
- 未绑定节点：`一键生成推荐流程`（含触发方式选择）+ `绑定已有流程`。
- 已绑定节点：编辑流程 / 切换触发方式 / 停用启用 / 解绑。
- 页头统计：已接入节点数、已绑定点数、待人工确认数、运行中实例数。
- 底部「最近等待确认的业务变更」列表。

### 2.3 流程设计器（`workflow_definition.html`）

- 顶部新增「触发这个流程」区块：选节点 + 触发方式；选「不绑定」保存时自动解绑。
- 从节点页点「生成」或带 `?event=` 进入时，自动预填流程 Key / 名称 / 分类 / 说明 / 审批步骤。
- 修复 v13.2 遗留缺陷：`tojson` 过滤器返回值被 Jinja 转义（`"` 变成 `&#34;`），内联到 `<script>` 后是语法错误，审批节点卡片与预览整块不渲染。改为返回 `Markup` 并对 `</` 做转义。

### 2.4 工作台（`index.html` + `app.py`）

- 「流程与审批」新增首个页签「待我发起（N）」，按条展示业务事项、触发节点、对应流程，提供「发起审批 / 忽略」。
- 管理员看全部待发起，普通用户只看自己触发的与未指定发起人的。

### 2.5 计划管理插件（`plugins/wbs`）

注册 5 个节点，并在真实业务动作后上报：

| 节点 | 上报位置 |
|---|---|
| `wbs.project.created` | `wbs_project_add` 提交后 |
| `wbs.project.approval` | `wbs_project_approve` 写回审批结果后 |
| `wbs.task.created` | `wbs_task_add`、`wbs_task_quickadd` 提交后 |
| `wbs.task.progress` | `wbs_task_inline` 改状态/进度但未完成 |
| `wbs.task.completed` | `wbs_task_inline` 进度到 100 或状态改已完成 |

上报统一走 `_emit_wf()` 包装：异常只写日志，不影响业务提交。

## 四、已知限制

- 节点级条件过滤未做（如金额阈值）：需要过滤时由插件判断后再调用上报。
- 一个节点只能绑定一条流程。
- 待发起不支持批量发起、转交。
- 外部插件 HTTP 上报端点未开放，规范中标注为后续契约。
- Windows 真机仍未验证启动（与 v13.2 相同）。

## 五、结论

v13.3 把「插件暴露状态节点 → 管理员绑定流程 → 业务人员一键发起」跑通了闭环，WBS 5 个节点已真实接入并在业务动作后触发。新增 45 项、存量 34 项回归全部通过，未发现回退。
