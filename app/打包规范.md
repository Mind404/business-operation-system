# 业务高效运转系统 — 打包规范（便携版）

> 每次打包交付前**必须**按本规范执行与校验。目标：解压后的文件夹与 v12.4.9 结构完全一致（含 Python 运行环境，拷贝即用）。

## 一、目标交付结构（唯一标准）

解压 `业务系统vX.Y.Z.zip` 后，必须得到：

```
业务系统vX.Y.Z/                    ← 文件夹名 = 版本号（与 zip 同名）
├── 0-先看这个.txt                 ← 使用说明（含版本号、更新要点）
├── 启动系统.bat                   ← 顶层入口，双击启动
├── 停止系统.bat                   ← 双击停止
├── 使用说明.txt                   ← 便携版说明（无需改动）
├── python/                        ← Python 运行环境（embeddable + 全部依赖，~26MB）
│   └── Lib/site-packages/         ← flask/werkzeug/jinja2/click/blinker/itsdangerous/waitress
└── app/                           ← 系统本体
    ├── 启动系统.bat（app内另一份，代码版入口）
    ├── app.py / plugin_system.py / ai_routes.py / config.py / db_migrations.py / ext_routes.py
    ├── plugins/（wbs、reqcollect 等）
    ├── static/ / templates/
    ├── business.db（含演示数据）
    ├── secret.key / schema.sql / requirements.txt / CHANGELOG.md
    ├── 一键打包便携版.bat / 后台启动(无窗口).vbs / 备份数据库.bat
    ├── 设置开机自启.bat / 设置每日自动备份.bat / 安装为Windows服务(需nssm).bat
    ├── 插件开发规范.md / 演示插件-样品管理.zip
    └── backups/
```

## 二、打包步骤（以 v12.4.9 zip 为基底）

1. **准备基底**：下载上一版交付 zip（如 `https://aka.doubaocdn.com/s/zw73sUOkFX`），解压得到完整便携版文件夹。基底提供不可重新生成的 `python/` 运行环境与三个顶层入口文件。
2. **版本改名**：把解压出的 `业务系统v上一版/` 重命名为 `业务系统vX.Y.Z/`。
3. **替换 app/**：
   ```bash
   rm -rf 业务系统vX.Y.Z/app && mkdir -p 业务系统vX.Y.Z/app
   rsync -a --exclude '.git' --exclude '__pycache__' --exclude '*.pyc' \
     --exclude '*.wal' --exclude '*.shm' \
     --exclude 'instance/*.db-wal' --exclude 'instance/*.db-shm' \
     <仓库根>/ 业务系统vX.Y.Z/app/
   ```
4. **更新 `0-先看这个.txt`**：改版本号，追加本版更新要点。
5. **打包**（必须 cd 到基底外层，zip 顶层 = 文件夹本身）：
   ```bash
   cd <基底父目录>
   zip -9 -r /tmp/业务系统vX.Y.Z.zip 业务系统vX.Y.Z \
     -x '*/.git/*' -x '*/__pycache__/*' -x '*.pyc' -x '*.wal' -x '*.shm'
   ```

## 三、交付前校验清单（逐项必查）

| # | 检查项 | 通过标准 | 检查命令 |
|---|---|---|---|
| 1 | 顶层结构 | 恰好 6 项：`0-先看这个.txt`、`启动系统.bat`、`停止系统.bat`、`使用说明.txt`、`python/`、`app/` | `unzip -l x.zip \| awk '{print $4}' \| awk -F/ 'NF>=2{print $1"/"$2}' \| sort \| uniq` |
| 2 | 无嵌套内部目录 | 顶层**不得**出现 `biz_pkg_*`、`_chk*`、`/tmp` 等内部命名 | 同上 |
| 3 | python 运行环境 | `python/python.exe` 存在，`site-packages` 含 7 个依赖 | `unzip -l x.zip \| grep 'python/python.exe'` |
| 4 | app 关键文件 | `app/app.py`、`app/启动系统.bat`、`app/business.db` 存在 | `unzip -l x.zip \| grep -E 'app/app.py\|app/启动系统.bat\|app/business.db'` |
| 5 | 本版改动落包 | 本轮改动的关键代码文件已更新（如 `reqcollect_sheet.html` 含最新修复标记） | 解压抽查 grep |
| 6 | 数据库 | `app/business.db` 为最新工作库（含演示数据），排除 `*.wal/*.shm` | `ls -lh` + 包内无 wal/shm |
| 7 | 无缓存垃圾 | 包内无 `__pycache__/`、`*.pyc` | `unzip -l x.zip \| grep -cE '__pycache__|\.pyc'` 应为 0 |

## 四、易错点（历史教训）

1. **把内部发布目录（如 `/tmp/biz_pkg_v1251`）直接打进 zip** → 解压多一层技术命名嵌套目录。必须 cd 到基底外层，让 zip 顶层 = `业务系统vX.Y.Z/`。
2. **只打 app 代码、漏掉 `python/` 与顶层 `启动系统.bat/停止系统.bat/使用说明.txt`** → 用户机器无 Python 无法运行。`python/` 不可本地重建，必须从上一版交付 zip 继承。
3. **`0-先看这个.txt` 版本号忘更新** → 保持与交付版本一致。
4. **把 `secret.key` 误排除** → 系统启动需要，必须随包。
5. **改版后直接 `zip 业务系统vX.Y.Z/`**（在文件夹内部打包）→ zip 内会出现该文件夹名自身的冗余路径。
