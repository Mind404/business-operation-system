# 业务高效运转系统 · 插件开发规范（v12.7.10.10）

> 平台定位：**单点登录 + 信息聚合 + 统一权限管理**。
> 具体业务由插件实现：**插件自己管理数据表和工作流程**，只要按本规范开发，
> 即可被平台接管（登录校验、三级权限、导航展示、启用/停用、表登记、操作日志）。

---

## 1. 平台接管范围（平台做什么 / 不做什么）

| 能力 | 归属 | 说明 |
| --- | --- | --- |
| 登录 / 注销 / 会话 | 平台 | 一次登录，访问全部插件 |
| 三级权限 | 平台 | platform_admin（平台管理员）/ admin（管理员）/ user（普通用户） |
| 导航展示 | 平台 | 插件在 manifest 声明入口，平台自动放入侧边栏 |
| 启用 / 停用 / 卸载 | 平台 | 平台管理员在「系统管理 → 插件管理」控制 |
| 表登记 | 平台 | 插件声明自己的数据表，登记到平台注册表（plugin_registry.tables） |
| 操作日志 | 平台 | 调用 `log_operation()` 统一记录 |
| **业务数据表** | **插件** | 插件自己建表、自己读写，平台不代建 |
| **业务流程 / 审批** | **插件** | 工作流（含审批）由插件自己实现，平台不提供统一审批 |
| **业务界面** | **插件** | 插件自带模板页面，继承平台 base.html 风格 |

## 2. 插件包结构

一个插件 = `plugins/<插件id>/` 目录下的一个 Python 包，结构如下：

```
plugins/
└── myplugin/                  # 目录名 = 插件 id（必须与 manifest.id 一致）
    ├── __init__.py            # 声明 manifest + 导出 blueprint
    ├── routes.py              # 业务路由（Flask Blueprint）
    ├── templates/             # 插件页面模板（可选，继承 base.html）
    │   └── my_index.html
    ├── static/                # 插件静态资源（可选）
    └── schema.sql             # 插件数据表定义（可选，插件自管）
```

放置方式二选一：
- **方式 A（放目录）**：把插件目录放进 `plugins/`，**重启系统**即自动注册；
- **方式 B（上传安装）**：把插件目录打包成 zip（`myplugin.zip`，zip 内第一层是插件目录），在「系统管理 → 插件管理 → 上传并安装」，平台自动解压、校验、注册（即时生效，无需重启）。

## 3. manifest 字段规范（`plugins/<id>/__init__.py`）

```python
manifest = {
    'id': 'myplugin',           # 必填：插件唯一标识，与目录名一致（小写英文）
    'name': '我的插件',          # 必填：显示名称
    'icon': '📦',               # 可选：导航图标（emoji）
    'group': '业务插件',         # 可选：分组名称，默认「业务插件」
    'core': False,              # 可选：True=核心常驻（不可停用/卸载）；业务插件一律 False
    'description': '一句话说明',  # 必填：功能说明（显示在插件管理页）
    'endpoint': 'myplugin.index',  # 必填：插件首页路由的 endpoint（用于导航与权限判定）
    'url_prefix': '/myplugin',     # 必填：插件所有路由的公共前缀（用于访问守卫与导航高亮）
    'tables': ['my_table_1', 'my_table_2'],  # 可选：插件数据表清单（登记到平台注册表，供插件管理页展示）
    'min_role': 'user',            # 可选：整站最低访问角色（user=所有登录用户/admin=管理员及以上/platform_admin=仅平台管理员）
                                   # 不声明 = 所有登录用户可访问（v12.2.0 平台自动拦截）
    'menu': [                        # 可选：插件内部多页面时可声明子菜单
        {'name': '列表', 'endpoint': 'myplugin.index', 'icon': '📋'},
    ],
}
```

约束：
- `id` 只允许小写字母、数字、下划线；
- `endpoint` 必须等于 `'<插件id>.<蓝图路由函数名>'`；
- `url_prefix` 与插件内所有路由前缀一致，不能与其他插件冲突。

## 4. blueprint 规范（`plugins/<id>/routes.py`）

```python
from plugins.base import make_blueprint   # 统一工厂：保证命名规范
from flask import render_template

blueprint = make_blueprint('myplugin', __name__)   # 第一个参数 = 插件 id


@blueprint.route('/myplugin')             # 首页：endpoint = myplugin.index
def index():
    return render_template('my_index.html')
```

- 必须通过 `plugins.base.make_blueprint` 创建（统一 blueprint 命名规范）；
- 插件所有路由建议都以 `url_prefix` 开头，便于守卫识别；
- 不要在 `app.py` 里硬编码注册插件路由——平台启动时自动扫描注册。

## 5. 平台接口

### 5.1 数据库（v12.4.5 更新：统一建表入口 + 表名平台接管）
```python
from plugin_system import get_db, create_plugin_table, get_table_name
db = get_db()                      # 返回 sqlite3 连接（row_factory=Row）
```
- 插件**自己建表、自己迁移**，但**建表必须通过平台统一入口** `create_plugin_table()`，
  禁止直接裸 `CREATE TABLE`（见 5.1.1 表名管理）；
- 表名**必须带业务前缀**（如 `demand_items`、`myplugin_items`），禁止裸表名；
  **推荐使用「插件id_」前缀**（如 `demand_a_items`）——插件 id 唯一，天然隔离永不撞名；
- 建表后可把表名登记进 manifest 的 `tables`，平台插件管理页会展示（含逻辑名→实际名映射）。

#### 5.1.1 表名管理（v12.4.5 新增：统一入口 + 撞名自动分配 + 重装不漂移）
分散开发的插件即使使用相同业务前缀（如都叫 `demand_items`），平台也能自动化解：

```python
# 建表（必须走统一入口；DDL 请写 CREATE TABLE IF NOT EXISTS 保证幂等）
actual = create_plugin_table('demand_a', 'demand_items', '''
    CREATE TABLE IF NOT EXISTS demand_items (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        name TEXT, status TEXT DEFAULT '未开始', created_at TEXT)''')
# actual = 'demand_items'（先装者）
# 若另一插件 demand_b 也声明 demand_items → 平台自动分配 'demand_items_2'，不报错、不混数据

# 读写时用 get_table_name() 取实际表名（插件代码不写死表名）
tbl = get_table_name('demand_b', 'demand_items')   # 返回 'demand_items_2'
db.execute(f'SELECT * FROM {tbl} WHERE id=?', (1,))
```

规则要点：
1. **表名必须带业务前缀**（含下划线，如 `xxx_items`），裸表名（`items`）直接拒绝；
2. **撞名自动分配**：同一表名被其他插件登记占用 → 平台自动分配 `表名_2`、`表名_3`…
   插件照常工作（读写都走 `get_table_name()`），插件管理页会黄标提示「自动分配」；
3. **推荐插件 id 前缀**（`demand_a_items`）：插件 id 由平台保证唯一 → 命名空间唯一 →
   正常开发永不撞名，是最佳实践；
4. **重装不漂移**：平台按插件 id 持久化登记映射，插件重装/升级沿用第一次分配的表名，
   业务数据原样找回（卸载插件时登记与数据表一并保留，与平台「卸载不删数据」约定一致）；
5. **时间戳后缀（可选）**：仅「一个插件按需动态生成多张同构表」场景使用平台工具函数
   `suffix_table_name(plugin_id, base_name)`（如 `xxx_202610261730`），
   它随时间变化，不可用于重装后仍需恢复数据的持久业务表；
6. **一致性校验**：平台启动时比对登记表与实际建表，登记未建表 / 裸建未登记会在
   启动日志与插件管理页红字提示，便于及时发现插件未走统一入口。

#### 5.1.2 建表时机（v12.6.9 补充：必须在请求上下文内调用）
`create_plugin_table()` / `get_db()` 依赖 Flask 请求上下文（`g`/`current_app`），
**禁止在插件模块顶层（import 时）调用**，否则插件加载报
`Working outside of application context` 并被跳过（上传安装后重启不生效、插件页 404）。

正确做法：与内置插件 `wbs`、`univer_sheet` 一致——在**路由函数内**（或
`before_app_request` 等请求上下文中）惰性建表，幂等即可：

```python
def _ensure_tables():                      # 集中定义建表
    create_plugin_table('myplugin', 'myplugin_items', '''
        CREATE TABLE IF NOT EXISTS myplugin_items (
            id INTEGER PRIMARY KEY AUTOINCREMENT,
            name TEXT NOT NULL,
            created_at TEXT DEFAULT (datetime('now','localtime')))''')

@blueprint.route('/myplugin')
def index():
    _ensure_tables()                       # 首次访问时建表（IF NOT EXISTS 幂等）
    db = get_db()
    ...
```

#### 5.1.3 数据隔离（v12.7.0 方案B：上传插件独立库）
平台对插件数据实施「方案B」隔离：
- **上传安装的插件**（插件管理页上传、install_type=upload）：其数据表自动建在
  **独立库 `app/data/<插件id>.db`**；主库只存登记（`plugin_tables`）与平台业务表，零污染。
- **内置插件**（wbs、univer_sheet 等随包发布）：仍使用主库，原有数据不受影响。
- **插件代码无需感知**：读写一律用 `plugin_system.get_db()`，系统按请求所属插件
  自动路由（上传插件→独立库，内置插件→主库）；建表仍用 `create_plugin_table()`。
- **卸载不删数据**：卸载插件时独立库文件保留（`app/data/<插件id>.db` 不删除），
  重装同一插件后表名沿用、数据自动找回；如确需彻底删除请手动删除对应独立库文件。
- **备份全覆盖**：平台启动自动备份主库 + 全部插件独立库，按前缀各保留最近 7 份。
- **AI 可读**：AI 助手上下文会自动只读注入各插件独立库的数据（标注插件来源）。

## 6. 三级权限使用约束（插件必须遵守）

| 角色 | 定位 | 插件内应开放的能力 |
| --- | --- | --- |
| `platform_admin` 平台管理员 | 系统级管理 | 全部（含系统管理入口） |
| `admin` 管理员 | 业务管理 | 插件内管理操作（增删改、审批、配置） |
| `user` 普通用户 | 业务使用 | 查看与提交（需要审批的变更走插件自己的流程） |

- 插件内部涉及「管理类」操作（新建/编辑/删除/审批/配置）必须做管理组校验
  （`role in ('platform_admin', 'admin')`），不能只靠隐藏按钮；
- 普通用户的破坏性操作（删除等）建议仅管理员可执行；
- 平台只负责登录与角色判定，**具体每个操作的权限由插件自己校验**。

## 7. 数据表与工作流自管

- **建表**：插件在启动或首次使用时**通过 `create_plugin_table()` 建表**（幂等，见 5.1.1），平台不代建；
- **迁移**：插件结构变更时自行处理（如 `ALTER TABLE ... ADD COLUMN` 前先查列）；
- **工作流/审批**：平台不提供统一审批。插件需要审批时，自己建审批表、自己实现
  「申请 → 审批 → 通过/驳回」与状态流转；
- **数据安全**：平台不做业务数据备份，插件应把重要数据放在自己的表里，
  由系统「备份数据库.bat」整体备份。

## 7.1 并发与写事务（v12.2.0 新增，多人协同场景必须遵守）

平台数据库为 SQLite，已开启 **WAL 模式**（读不阻塞写、写不阻塞读），但同一时刻
只能有一个写事务提交。20~80 人协同场景下必须遵守：

- **一律通过 `plugin_system.get_db()` 取连接**，禁止自己 `sqlite3.connect` 另开库
  （否则拿不到 WAL 配置且可能与平台连接互相锁库）；
- **多表写入必须包成事务**（一次请求内多次 `execute` 后统一 `commit`），
  避免每条语句单独提交导致的锁竞争；
- **不要开长事务**：事务内不要做网络请求、文件 IO、等待等耗时代码；
- **写操作失败要 `rollback()`**，并给用户明确报错提示；
- 读多写少的页面（列表、统计）不强制事务，但查询要带 `LIMIT` 防止大表全扫；
- 平台线程数已扩容至 16，单人请求不应占用超过几百毫秒的数据库时间。

## 7.2 表隔离（v12.2.0 新增）

- 插件只能读写**自己的表**（表名带业务前缀，推荐「插件id_」前缀）；
- **禁止** `ATTACH DATABASE`、直接读取其他插件/平台的表（含 `users` 表）；
- 需要用户信息时只用平台注入的 `session` 与 `{{ current_user }}`；
- 需要操作日志时调用 `log_operation()`，不要自己往 `operation_logs` 插数据。

## 7.3 错误处理（v12.2.0 新增）

- 数据库异常必须捕获：`except Exception as e:` 里 `db.rollback()` 并
  `flash('操作失败：' + str(e), 'error')`，不要裸奔让用户看到 500 页；
- 允许 `except: pass` 的场景只有「日志写入等非关键路径」，且应注释原因；
- 表单必填校验在服务端再做一次（前端隐藏不等于安全）。

## 8. 安装 / 启停 / 卸载

| 操作 | 入口 | 效果 |
| --- | --- | --- |
| 安装 | 放 `plugins/` 目录重启，或管理页上传 zip | 自动登记注册，立即/重启后生效 |
| 启用/停用 | 插件管理页 | 停用=隐藏导航+拦截访问；业务数据不动；可随时启用 |
| 卸载 | 插件管理页（仅上传安装的插件） | 删除插件包目录；**业务数据表保留**（防误删） |
| 内置插件 | WBS 等 | 可停用，不可卸载 |

卸载/删除插件包后，平台注册表与订阅记录会自动清理，业务数据表不受影响。

## 11. 常见问题

- **上传后访问 404？** 检查 zip 第一层是否为插件目录；manifest.id 是否与目录名一致；
  `endpoint` 是否等于 `插件id.路由函数名`；`url_prefix` 是否与实际路由前缀一致。
- **导航里没有我的插件？** 确认 manifest 完整（id/name/endpoint/url_prefix）、
  插件未被停用、插件首页 endpoint 存在。
- **停用后还能直连 URL？** 不应发生：平台守卫按 `url_prefix` 拦截已停用插件，
  请确认 manifest 的 `url_prefix` 覆盖了插件所有路由。
- **想删掉插件的数据？** 卸载只删代码保留数据；需要连数据一起清除时，
  手动在数据库中删除对应表（或插件提供清理入口）。

## 12. 数据开放要求（强制，v12.7.10.10 升级）

平台 AI 要能分析"全平台"的数据，包括每个插件产生的业务数据。**数据开放不是可选项，是插件能否上线的硬指标**：插件在开发阶段就必须把全部业务数据按本章与 §13 的约定开放出来，不允许私藏、不允许只开放一部分、不允许等到上线后再补。

### 12.1 一条底线：插件数据必须对平台开放

| 要求 | 说明 |
| --- | --- |
| 全部业务表都要开放 | 插件自己的业务数据表（含主表、明细表、日志表、配置表）一个都不能少；§13 的 `datasets` 必须列全 |
| 开发时就实现，不是上线后补 | 打包上传时平台会当场探测；没有开放接口的插件，管理页会标红"未实现"，AI 只能直读兜底 |
| 数据放在平台约定位置 | 外来插件的表建在 `app/data/<插件id>.db`（见 §5.1.3 数据隔离），不允许写到插件目录私有文件或外部库 |
| 不允许用"不开放"规避 | `ai_readable: False` 只保留给**含个人隐私/合同原文/薪酬**等确需保护的表，并在 `description` 里写明原因；滥用视为不达标 |
| 敏感字段必须自己处理 | 密码、令牌、密钥、身份证、手机号等，插件要么不落库，要么按 §13.4 第 6 条脱敏后再出现在接口里 |

### 12.2 平台怎么用这些数据（插件作者需要知道的两点）

1. 平台 AI 读取时会**跨全部插件汇总**，据此回答"全平台视角"的问题；某个插件不开放，答案里就缺这块业务，并且会在上下文里显式标注"该插件未提供数据"，不会假装读过。
2. 平台调用插件接口是**进程内直调**（不发起 HTTP、不经过登录校验、不需要插件对外开放端口），因此插件不需要处理鉴权、CORS、跨域，只要把数据按格式返回即可。

### 12.3 两种通道与优先级

| 通道 | 适用 | AI 上下文里的标注 |
| --- | --- | --- |
| **OpenAPI v1 接口**（推荐、达标线） | 所有新开发/新上传插件 | "外部插件「X」开放数据（OpenAPI v1 接口，N 张有数据表）" |
| 直读独立库（兼容兜底） | 没有实现接口的存量插件 | "…（该插件未实现数据开放接口，平台直读其独立库，属兼容兜底）" |

**新插件一律按 §13 实现接口**；直读兜底只是给老插件留的过渡通道，不作为达标方式。

## 13. 数据开放接口约定（OpenAPI v1）

插件必须在自己 `url_prefix` 下实现两个**只读** GET 接口。完整可复制代码见 §13.6。

### 13.1 接口一：数据集清单

```
GET <url_prefix>/__openapi/datasets
```

返回该插件**全部业务表**的清单（无参数）：

```json
{
  "openapi": 1,
  "plugin": "myplugin",
  "tables": [
    {
      "name": "myplugin_items",
      "label": "物料齐套清单",
      "primary_key": "id",
      "time_field": "created_at",
      "rows": 128,
      "description": "一行 = 一个物料；status 表示齐套状态",
      "sensitive": false,
      "fields": [
        {"name": "id", "type": "integer", "label": "编号"},
        {"name": "item_name", "type": "text", "label": "物料名称"},
        {"name": "status", "type": "text", "label": "状态"}
      ]
    }
  ]
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `openapi` | 是 | 固定 `1`，版本号；平台按此识别 |
| `plugin` | 是 | 插件 id，须与目录名/manifest.id 一致 |
| `tables` | 是 | 数组；没有数据的表也要列出（`rows: 0`） |
| `tables[].name` | 是 | 真实表名（英文，与库里一致） |
| `tables[].label` | 建议 | 中文名，AI 回答里用它，比英文表名好懂 |
| `tables[].primary_key` | 建议 | 主键列名，AI 引用原始行时用 |
| `tables[].time_field` | 建议 | 时间列（如 `created_at`），AI 做趋势/时间对比时用 |
| `tables[].rows` | 是 | 当前行数（整数），平台据此判断"有数据/空表" |
| `tables[].description` | 建议 | 一句话口径说明，直接影响 AI 理解是否正确 |
| `tables[].sensitive` | 可选 | 整表含敏感信息时置 `true`，平台会在上下文里提示"该表含敏感字段" |
| `tables[].fields` | 建议 | 字段数组，`name` 必须与真实列名一致 |

### 13.2 接口二：分页取数

```
GET <url_prefix>/__openapi/rows?table=<表名>&limit=<每页行数>&offset=<起始行>
```

| 参数 | 必填 | 约束 |
| --- | --- | --- |
| `table` | 是 | 必须是 `datasets` 里出现过的表名；**不在白名单一律拒绝**（防止 SQL 注入与越权读取平台表） |
| `limit` | 否 | 默认 100，平台最大传 1000；插件侧也要夹紧上限 |
| `offset` | 否 | 默认 0，非负整数 |

响应：

```json
{
  "openapi": 1,
  "table": "myplugin_items",
  "offset": 0,
  "limit": 100,
  "total": 128,
  "fields": ["id", "item_code", "item_name", "status", "created_at"],
  "rows": [
    {"id": 1, "item_code": "M-001", "item_name": "射频连接器", "status": "齐套", "created_at": "2026-11-09"}
  ]
}
```

- `rows` 里每行是一个对象，键 = 列名；日期时间统一转字符串（`YYYY-MM-DD HH:MM:SS` 或 `YYYY-MM-DD`）；
- 排序必须稳定（建议 `ORDER BY <primary_key>` 或 `time_field DESC`），否则分页会漏行/重复行；
- 出错时返回 4xx + `{"openapi": 1, "error": "说明"}`，不要抛 500 堆栈。

### 13.3 平台侧的调用方式（插件不用做鉴权）

- 平台在自己的进程里直接调用插件的视图函数（Flask `view_functions`），**不发 HTTP 请求**，所以不需要登录态、不需要 token、不需要开放端口；
- 调用带的是内部请求上下文，插件视图里可以正常使用 `request.args`；
- 平台单次最多取 1000 行、按 `offset` 翻页；接口必须支持任意 `offset`。

### 13.4 硬约束（违反任一即为不达标）

1. **只读**：两个接口不得写库、不得删改数据、不得触发业务动作（不得发消息、不得调外部系统）。
2. **列全**：`datasets` 必须包含本插件全部业务表；故意漏表 = 数据不开放。
3. **表名白名单**：`rows` 必须校验 `table` 在 `datasets` 名单内，禁止把参数直接拼进 SQL。
4. **不碰平台系统表**：不得返回 `users`、`operation_logs`、`user_sessions`、`ai_providers`、`plugin_registry` 等平台表数据。
5. **分页稳定**：必须支持 `limit/offset`，并保证同一次遍历不重复、不遗漏（稳定排序）。
6. **敏感字段脱敏**：密码、令牌、密钥、身份证、银行卡、手机号等必须排除或掩码（如 `138****0000`）后再返回；`datasets` 里可用 `sensitive: true` 标注整表。
7. **性能**：单次 `rows` 调用 ≤ 200ms（万行以内表），不得全表加载到内存再切片；数据量大时按主键范围查询。
8. **响应体积**：单次响应 ≤ 5MB；超了说明 `limit` 没夹紧。
9. **不依赖登录用户**：接口返回的是"插件全部数据"，不得按当前登录人过滤（平台 AI 需要全量口径）。

### 13.5 平台 AI 怎么读（插件作者据此判断字段是否够用）

1. 先调 `datasets` 拿到全部表名、行数、字段；
2. 跳过 `rows = 0` 的空表，其余表按 `limit=2 / offset=0` 取样例注入上下文（含总行数与字段清单）；
3. 问题相关时继续按 `offset` 翻页续读，直到预算用尽或读完；
4. 每张表的数据都会标注来源插件名与表名，AI 结论里可回溯到原始行。

因此：**表要有可读的业务列**（编号、名称、状态、数量、负责人、时间），只存一段 JSON 大字段的表，AI 读到了也分析不出东西。

### 13.6 可直接复制的实现代码

`plugins/myplugin/__init__.py`：

```python
# -*- coding: utf-8 -*-
from .routes import blueprint

manifest = {
    'id': 'myplugin',
    'name': '我的插件',
    'icon': '🧩',
    'group': '业务插件',
    'core': False,
    'description': '一句话说明插件用途',
    'endpoint': 'myplugin.index',
    'url_prefix': '/myplugin',
    'tables': ['myplugin_items'],
    'data_open': {
        'ai_readable': True,
        'description': '物料齐套清单，一行 = 一个物料',
    },

```

`plugins/myplugin/routes.py`（数据开放接口部分）：

```python
# -*- coding: utf-8 -*-
import os
import sqlite3
from flask import Blueprint, render_template, request, jsonify

blueprint = Blueprint('myplugin', __name__, template_folder='templates')

PLUGIN_ID = 'myplugin'
# 插件数据统一在 app/data/<插件id>.db（相对插件目录往上三层）
DB_PATH = os.path.join(
    os.path.dirname(os.path.dirname(os.path.dirname(os.path.abspath(__file__)))),
    'data', PLUGIN_ID + '.db')

# 这里登记本插件的全部业务表（漏表 = 数据不开放）
DATASETS = [
    {'name': 'myplugin_items', 'label': '物料齐套清单',
     'primary_key': 'id', 'time_field': 'created_at',
     'description': '一行 = 一个物料；status 表示齐套状态'},
]

SENSITIVE_COLS = ('password', 'token', 'secret', 'credential',
                  'id_card', 'bank_card', 'phone')


def _connect():
    c = sqlite3.connect(DB_PATH, timeout=3.0)
    c.row_factory = sqlite3.Row
    return c


def _public_cols(cols):
    """敏感列不出接口"""
    return [c for c in cols
            if not any(k in c.lower() for k in SENSITIVE_COLS)]


@blueprint.route('/myplugin/__openapi/datasets')
def __openapi_datasets():
    out = []
    c = _connect()
    try:
        for d in DATASETS:
            tab = d['name']
            try:
                cnt = c.execute('SELECT COUNT(*) FROM "%s"' % tab).fetchone()[0]
                cols = [r[1] for r in c.execute('PRAGMA table_info("%s")' % tab).fetchall()]
            except Exception:
                cnt, cols = 0, []
            out.append({
                'name': tab,
                'label': d.get('label', tab),
                'primary_key': d.get('primary_key', 'id'),
                'time_field': d.get('time_field', ''),
                'description': d.get('description', ''),
                'rows': cnt,
                'sensitive': False,
                'fields': [{'name': x, 'type': 'text', 'label': x}
                           for x in _public_cols(cols)],
            })
    finally:
        c.close()
    return jsonify({'openapi': 1, 'plugin': PLUGIN_ID, 'tables': out})


@blueprint.route('/myplugin/__openapi/rows')
def __openapi_rows():
    table = (request.args.get('table') or '').strip()
    allowed = {d['name'] for d in DATASETS}
    if table not in allowed:                     # 表名白名单，防注入/越权
        return jsonify({'openapi': 1, 'error': 'unknown table'}), 400
    try:
        limit = max(1, min(int(request.args.get('limit', 100)), 1000))
        offset = max(0, int(request.args.get('offset', 0)))
    except Exception:
        limit, offset = 100, 0
    c = _connect()
    try:
        total = c.execute('SELECT COUNT(*) FROM "%s"' % table).fetchone()[0]
        cols = _public_cols([r[1] for r in c.execute('PRAGMA table_info("%s")' % table).fetchall()])
        if not cols:
            return jsonify({'openapi': 1, 'table': table, 'offset': offset,
                            'limit': limit, 'total': total, 'fields': [], 'rows': []})
        sql = 'SELECT %s FROM "%s" ORDER BY "%s" LIMIT ? OFFSET ?' % (
            ', '.join('"%s"' % x for x in cols), table,
            next((d.get('primary_key') for d in DATASETS if d['name'] == table), cols[0]))
        rows = [{k: (v if not hasattr(v, 'isoformat') else v.isoformat())
                 for k, v in dict(r).items()}
                for r in c.execute(sql, (limit, offset)).fetchall()]
    finally:
        c.close()
    return jsonify({'openapi': 1, 'table': table, 'offset': offset, 'limit': limit,
                    'total': total, 'fields': cols, 'rows': rows})
```

### 13.7 上线前自检（一条命令验完）

启动系统后，在浏览器或命令行访问（把 `myplugin` 换成你的插件 id）：

```
http://127.0.0.1:5000/myplugin/__openapi/datasets
http://127.0.0.1:5000/myplugin/__openapi/rows?table=myplugin_items&limit=2&offset=0
```

| 检查项 | 通过标准 |
| --- | --- |
| datasets 可访问 | 返回 JSON，`openapi: 1`，`tables` 列出**全部**业务表 |
| 行数正确 | 每张表的 `rows` 与实际库内行数一致 |
| rows 可取数 | 传入表名能拿到数据且字段完整，日期是字符串 |
| 白名单生效 | 传 `table=users` 返回 400，而不是返回数据 |
| 分页稳定 | `limit=2&offset=0` 与 `limit=2&offset=2` 无重复行 |
| 无敏感列 | 返回的 `fields`/`rows` 里没有密码、令牌类字段 |
| 平台识别 | 插件管理页该插件显示"数据开放接口：已实现（AI 可读 N 个数据集）" |
| AI 可见 | AI 智能分析选"全平台数据"时，出现"外部插件「插件名」开放数据（OpenAPI v1 接口…）" |

### 13.8 不实现 / 不达标的后果

| 状态 | 平台行为 |
| --- | --- |
| 接口完整 | AI 按接口读全量数据，标注"OpenAPI v1 接口" |
| 接口缺失/格式不符 | 管理页标黄"未实现"；AI 回退直读 `app/data/<id>.db`，并标注"直读兜底"；上传安装时 flash 当场提示需补齐 |
| 接口拒绝特定表 / 漏表 | AI 只能看到开放的那部分，缺失部分不假装读过 |
| 声明 `ai_readable: False` | AI 明确写"该插件声明不对平台 AI 开放，已跳过"；仅限隐私/合同/薪酬等正当理由 |

插件管理页的徽标、上传时的提示、AI 上下文里的来源标注，三处会一致反映同一个状态——**不会出现"管理页说开放了、AI 却读不到"的错位**。
